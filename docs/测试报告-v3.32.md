## 六、已知限制（如实写，不当成缺陷）

1. **模型的稳定性只能收窄、不能消除。** 同一份输入，实测会出现答「无」的情况（本轮真调用第二次即如此）。工具的位置是「多一双眼睛」，结果与规则检查分开展示、以规则为准；答「无」时页面给的是「这一遍没提出语义层问题」，不是「没有问题」。
2. **自检工具的联跑需要本机有 Python。** 页面内的规则引擎不依赖它，跨引擎比对才用。
3. **任务的类型分派是按现有 5 个交付物类型写的。** 将来新增交付物类型时，`aiSpec()` 需要同步指定它属于整理型还是核稿型；`test_edge.js` 的 B 组会守住这条。

## 八、v3.33 追加：布局与格式检查

**为什么加这一套**：用户在截图里看到第 1 步标题「备齐清单与配置」被截成「备齐清单与配」，并说「不止这一项」。前面五套测试都查不出这类问题——它们看的是代码行为和数据，看不到画出来的东西。

### 查到的问题与根因

| 现象 | 根因 |
| --- | --- |
| 标题溢出卡片、压到隔壁 | 图的总宽写死 860 再按步数均分，8 步时卡片只有 74.5px，而换行按固定 7 字（87.5px）切 |
| 标题第二行与底部小字叠在一起 | 第二行 y=by+56、底部小字 y=by+54，同一位置 |
| 断词难看（「…判断」只剩一个字一行） | 按字数硬切，不看词 |
| 字被拉大后更挤 | CSS `width:100%` 把 860 的 viewBox 拉伸到容器宽 |

### 改法

列宽固定 150、总宽按步数算（6 步 988 / 7 步 1138 / 8 步 1288）；每行字数按卡片实际宽度算；断行遇连词或标点则切在其后，第二行只剩一个字时前移一个字；卡片高 62 → 92，四行各就各位；图加 `max-width`，容器更宽也不放大。

### 检查怎么做

```
python test_layout.py
```

一条命令：渲染 11 个任务 → 导出可测量的 HTML → 用 headless 浏览器量**真实文字包围盒** → 判定四类问题。

1. 卡片有没有跑出泳道
2. 每段文字有没有完整落在卡片里（左右上下都留白）
3. 同一张卡片里左侧对齐的两行有没有相叠
4. 介入标签横向有没有压到一起

**结果：11 / 11 全部通过。**

**为什么这一套是 Python 而不是 js**：这台机器上 node 被禁止派生任何子进程——试过 `spawnSync`、`execFileSync`、`execSync`，连 `cmd.exe` 都返回 EBUSY，换成系统装的 node 也一样。而调浏览器正是要派生子进程，所以把活拆开：`render_flows.js` 只负责渲染（读文件、算 SVG，不派生任何东西），`test_layout.py` 负责调 Chrome 与判定。

**两条命令就够**：`python test_layout.py`（它会自己先调 node 渲染）。

**另外两个坑，都是这次踩到的**：

1. **不能给 `global.URL` 赋一个普通对象**。node 的文件代理内部要做 `x instanceof URL` 判断，覆盖之后 `readFileSync` 直接报 `Right-hand side of 'instanceof' is not callable`——冒烟、边界、布局三个测试一起挂。只补 `createObjectURL` 方法，别换构造函数。
2. **破坏性测试必须有兜底还原**。负向测试第一版没有 try/finally，脚本崩在还原之前，把破坏态的文件（`var per = 20;`）留了下来；下一轮读到的「原始文件」本身是坏的，于是「正常情况 9/11」这种莫名其妙的结论就出来了。现在加了自愈：启动时若发现上次留下的备份，先还原；再加前置校验，文件状态不对就拒绝运行。


### 检查脚本自己也有两个 bug，被负向测试抓出来

1. **字段名写错**：存进去叫 `h:`，读的是 `.height`，算出来恒为 NaN，`NaN < 1.5` 永远为假——**行间距这段检查从来没生效过**
2. **归属条件只按 y 判断**：把同一泳道相邻卡片的文字当成一张卡片的行，凭空报「相叠」

两条都改掉。并把这个教训固化进写法：**阈值判定一律写成 `!(值 >= 阈值)` 而不是 `值 < 阈值`**，这样字段名再写错会当场报出 NaN，而不是静默通过。
