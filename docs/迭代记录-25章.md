## 一、设计期定下的

### 1. 不采用旧稿，另行新建

根目录原有一份 `AI协作流程引导器.html`。**逐行读过之后决定不复用**：它给的是「任务解析、资料检索、事实校验、判断取舍、交付质检」这套固定的五步，每个任务类型下面挂的是四张清单，**没有「AI 做什么 / 人做什么 / 交接点 / 产出物 / 出错怎么办」**——而这五项正是这次要做的核心。它的形态是「提醒你别忘」，不是「告诉你这条任务怎么走」。

### 2. 任务类型只做两个，从十二项里选

选择标准是两条同时满足：**两条线各占一个**，以及**自动化形态不同**。

- **玩家反馈日报**（产品运营线）：以可完全替代的机械动作为主，每天发生，释放的人时最多。
- **活动上线前检查**（活动运营线）：以可大部分替代的对照核对为主，错误代价最高，最能体现「错误代价能否决其他一切准则」。

如果两个都选「上线前核对」型，看起来铺了两个，实际是一个。

### 3. 「采集与规范化」和「分类打标」必须拆成两步

初稿里这是一步。写完后发现**交接点说不清**：人是在收料后交接，还是打标后交接？两件事的替代档位也不同（收料是档一，打标有档四成分），混在一起标哪个都不对。拆开后，第 2 步的交接点是「人→AI→人」，第 3 步是「AI→人」，两处都说得清了。

### 4. 每一步标的档位，是给机器那部分的档位

第一版没交代这一点，会出现读不通的地方：第 3 步「分类打标」标的是档一（可完全替代），可步骤里明明有人在裁定跨类条目。

**改动：** 在判定依据里写明——档位评的是这一步里交给机器的那部分，不包含留给人判断的那部分。这句写清楚之后，「档一 + 有人要拍板」不再矛盾，而是这条流程要说的那件事本身：**机器做执行，人做规则。**

### 5. 活动线最后一步收边，不越界到别的任务

原来第 6 步叫「上线后监控与检查表沉淀」，内容是盯指标、出告警、处置异常。**问题在于：盯指标与处置异常属于「活动期间数据监控」这条独立任务，把它塞进「上线前检查」会让这一步对应不上任何一个岗位任务。**

**改动：** 改名「放行后回补」，产出收回到检查表本身——盯上线后的表现，是为了判断这次检查表有没有漏项；异常处置明确交还给活动期间数据监控那条任务。

## 二、校验时被证据逼出来的

### 6. 页面上「交接点」显示不全（真缺陷）

**怎么发现的：** 冒烟测试断言「页面上应该搜得到完整的交接点文本」，结果 12 个步骤全部失败。

**根因：** 渲染时为了做视觉强调，把交接点字符串逐字符拆开加空格，`人→AI` 在页面上成了 `人 → A I`。**改动：** 改为原样输出，强调改用 CSS 字距。

### 7. 三条真实行业检查项在流程里找不到归宿（最有价值的一次）

**怎么发现的：** 前两条校验只能证明「该有的字段都在」，证不了「流程盖得住真实业务」。于是把四份真实公开清单里的检查项逐条提取出来，共 22 条，19 条判为范围内，然后要求每一条都能在流程的某一步找到归宿——找不到就算失败。

**首跑抓出 3 条无归宿：**

| 检查项 | 出处 | 性质 |
| --- | --- | --- |
| i13 灰度与试运营闭环 | 国内手游上线全流程解析 | **漏了一整步**：原流程从「风险排查」直接跳到「回滚预案」，中间没有走查环节 |
| i18 知识产权（素材授权或原创） | Design The Game | **排查项漏了**：第 3 步只写到内容审核与数据合规 |
| i19 无障碍（色盲模式、字号、按键重映射、字幕） | Design The Game | **排查项漏了**，同上 |

**改动两处：** 活动线新增第 4 步「测试服走流程与灰度验证」；第 3 步排查范围扩充到素材授权与知识产权、无障碍与多语言适配。

**同时把这次检查固化进校验脚本：** 行业检查项登记在数据块里，每条标出处与「范围内 / 范围外」；脚本检查范围内每一条是否都被某一步吸收，范围外每一条是否写了理由。**这条检查以后每次跑都会执行，防止流程改动时又漏掉环节。**

## 三、按使用反馈重做的（v2、v3、v3.1）

### 8. 版式重做：信息分成两层（v2）

**反馈：** 工具「特别的乱，文字也特别多，看得我头晕，不知道怎么用，排版什么的都有问题」。

**根因：** 原版把每一步的全部内容——AI 动作、人动作、需要的信息、要拍的板、交接说明、出错处置、判定依据、出处——平铺在一个卡片里，13 步 × 8 块 = 一百多块信息同时可见。这些信息的权重完全不同：动作是要执行的，依据和出处是给人查证用的。混在一起的结果是什么都不突出。

**改动：**
- 分成两层：主干层（这一步要达成、AI 做什么、人做什么、交接点、产出物）默认可见；细节与证据层（需要的信息、要拍的板、出错怎么办、判定依据、出处）折叠
- 打开页面默认选中第一个任务，不再是一片空白
- 每个步骤新增一句短句字段 `brief`，长度上限 40 字，**由校验脚本强制**，防止再堆长句

### 9. 主视图换成流程图（v3）

**反馈：** 「还是特别多的文字，看看能不能搞成多点图片多点流程，少点文字」。

**改动：**
- 主视图由卡片列表改为**一张流程图**：每个步骤一个节点（编号＋步骤名），右侧一条四格刻度条表示替代档位，节点之间是带方向的箭头，箭头上标交接方向
- 颜色分两类：**金色＝以机器为主，青色＝以人为主，紫色＝交接**
- 步骤细节不再平铺，**一次只显示当前选中的那一步**，点流程图上的节点切换
- 关键数字单独用数字卡呈现：几步流程、几处交接点、几步以机器为主、几步以人为主
- 「现在怎么做、卡在哪」压成一行

**这一步顺手改掉了一个度量口径的错误：** 原来的「首屏文字量」算的是数据字段长度，v3 之后那些文字进了图形和抽屉，数字不再对应真实可见内容。改成品面口径重算：**首屏约 610 字**，其中大部分是当前选中那一步的细节；全部展开才回到 3000＋字。

### 10. 与自检工具的对接从「提一句」变成「真接通」（v3.1）

**反馈：** 「怎么没有和之前的一些功能联合起来达到更好的自动化？」

**原来的问题：** 流程最后一步只写了「交给自检工具跑五个模块」，但没说明是哪个交付物类型、跑哪几个模块、怎么跑。人走到这一步还是要自己去翻自检工具的配置。这等于**把接口写了，没把接口接通。**

**改动：**

1. **绑定真实类型。** 每个任务绑定自检工具里的真实交付物类型：玩家反馈日报 → `feedback_table`；活动上线前检查 → `launch_check`，另附 `config_checklist`。
2. **标注实际会跑的模块。** A 数据／C 结构／D 一致性／E 来源；**B 表述检查在该两类交付物上被划掉**——这两类规则里没有禁用词与软性词，跑了也是空转。这不是省略，是省掉空转。
3. **必含栏目前移。** 把该类交付物的必含栏目直接列在页面上，写的时候就对齐，而不是等交出去才被拦。检查前移本身就是自动化收益。
4. **新增启动器 `跑自检.py`。** 自检工具读的是自己目录下的 `checklist.json`，原来每次要跑都得手改 `target` 与 `target_type` 两个字段——这一步机械、容易改错，正好该自动化。启动器把自检工具复制一份到 `_run/`、只改副本里的两个字段、在副本里跑，**不改动 `运营自检/` 里的任何文件**（跑完核对过，`checklist.json` 仍是原值）。
5. **对接校验进脚本。** 流程里写的类型、必含栏目、模块对照，每次都与 `运营自检/checklist.json` 逐项比对；自检工具的规则改了而本工具没跟上，校验直接失败并指出差在哪。模块对照不是手写的：脚本按「该类规则里有没有禁用词或软性词」判定 B 是否适用，再和流程里写的比。

**为什么不用命令行传参：** 查过 `run_all.py`，它用 subprocess 逐模块运行，各模块自己从磁盘读 `checklist.json`；`common.py` 里虽然有一套 `set_target / set_type` 覆盖接口，但那只在进程内生效（评测脚本用），传不到子进程。所以走「复制副本」这条路，代价是多复制 8 个脚本文件，收益是绝不碰已定稿的工具本体。

## 四、先检索再动手（v3.2）

### 11. 主视图与分工记法换成行业标准

**反馈：** 「你自己想的怎么可能有别人打磨好了的效果好？」——这句话是对的，而且指出了前三版共同的毛病：**画法和记法都是我现编的。**

**查出的三件事，每件都直接否掉了我的做法：**

| 我原来做的 | 行业里的做法 | 出处 |
| --- | --- | --- |
| 自己设计的"六要素卡片"，交接点写在步骤里 | **泳道图**才是画「谁做什么、交接在哪」的标准记法，交接就是跨泳道箭头，而且交接点要标注可能出什么问题 | Humane Design《Swimlanes》；LucidFlow《Swimlane Diagrams》 |
| 自己设计的"AI 做什么／人做什么"两栏 | **RACI** 是分工的标准记法，且有一条硬规则：**A（负责）必须始终是人**，这是责任要求不是技术限制 | First Line Software《The 2026 RACI for Acting AI Systems》；Ascendient《Leading Human-AI Teams》 |
| 把全部内容平铺一屏 | 细节分三层：概览 → **泳道（谁做什么、什么顺序、哪里断）** → 单步作业细节。"机器会无限展开细节，人的职责是选对层级" | skill.re《AI-Assisted Process Mapping》 |

**改动：**

1. **主视图改成泳道图**：上泳道＝机器，下泳道＝人。每个步骤落在执行方（R）所在泳道，交接画成跨泳道箭头，另一侧的介入（C）画成虚线连过去的小标签。

## 五、把能自动的收回机器（v3.3）

**反馈：** 「有很多地方也是可以完全做到自动的，结果还是留给了人做！」

**这条批评是对的，而且是我自己写出来的自相矛盾。** v1 起我在每一步标了替代档位，其中 6 步标的是「档一 可完全替代」——可每一步我又都安排了人的常规动作（逐条看、抽检、复看）。**档位说机器能全接，动作却全留给人。** 更难看的是，我在 v3.2 的检索里读到过「自主＝人只处理例外」，读到了，没用。

**改动：**

1. **每一步新增自动化档位**：`全自动`（常规路径无人）／`例外制`（机器全量做完，人只看被标出的少数）／`人复核`／`人决策`。
2. **逐条重定，把能收的收回机器**：
   - 采集与规范化 → **全自动**，原来写「人抽查」，改成「仅在某个渠道取不到数据时人工补摘」
   - 分类打标 → **例外制**，人只看待确认条目
   - 逐项对照（活动线） → **例外制**，人只看不一致项
   - 测试服走流程 → **例外制**，走查由脚本跑完，人只看报出的问题
   - 交付前自检 → **例外制**，报告为空即直接放行
   - 定口径 → 仍是人决策，但常规期**无口径变更就机器沿用上一版直接开工**，人只在有变更时介入
3. **关键数字换成实话**：原来显示「几步以机器为主」，换成「**N 步常规路径无需人工** 」与「M 步仍需人参与」。
4. **泳道图跟着变**：全自动的步骤不再画人；例外制的步骤另一侧只标「例外」。
5. **校验脚本加了三条硬规则**（防止再犯同类毛病）：
   - 自动化档位必须与替代档位匹配：档一 → 全自动／例外制；档四 → 只能人决策
   - **标了「全自动 / 例外制」的步骤，人的动作必须写成例外处理**（不含「仅／例外／异常／只」就判失败）
   - 例外标签数量必须与例外制步骤数一致

**结果：13 步里 6 步常规路径不占人（1 步全自动、5 步例外制），7 步仍需人参与（3 步人复核、4 步人决策）。** 这个数是从数据里算出来的，不是标上去的。

**顺带改掉一处旧结论：** 上一版依据区写着「13 步全部处在辅助段、自主 0 步」——那是个防守式的说法，等于承认一步都没往前推。现在按实际情况分开统计。

## 六、把自检引擎搬进页面（v3.4）

**反馈：** 「这个完全不需要人来参与了吧，你就不能集成进来吗？」

**批评成立。** 前三版到了交付前自检这一步，做法是让使用者自己去开终端、改 `checklist.json` 的两个字段、再敲一条命令。**这本身就是一道多余的人工序**——而这还是我在讨论「怎么把人从重复执行里解放出来」的工具。

**改动：**

1. **五个检查模块按 Python 逻辑逐行移植到页面内**（A 数字与出处／B 禁用表述／C 栏目覆盖／D 同一指标多值含名称归一化／E 引用可查性）。不是凭印象重写，是先把五个 `.py` 读完之后对着移植。
2. **规则内嵌**：`global_rules` 与五类交付物的栏目、禁用词、软性词全部嵌入页面数据区，取自 `运营自检/checklist.json`。
3. **界面改成粘贴即跑**：粘初稿，或点「选文件」直接读本地 `.md`／`.txt`；点「跑自检」出报告，格式与自检工具一致（严重度／行号／原文／问题／建议），末尾给「待处理项合计」。
4. **活动线还多一个「另跑一次」按钮**：同一份稿子再按 `config_checklist` 跑一遍，不用切任务。
5. 自检这一步的「AI 需要的信息」从「自检工具的规则文件」改成「初稿全文」——**不再需要任何外部文件**。

**加了两道防漂移的锁，防止两边算出不同的数：**

- **跨引擎比对**（写进 `smoke_test.js`）：拿四份 golden 样例，页面引擎与自检工具各跑一遍，**数必须完全一样**。当前结果：15／6／9／5 项，四份全部一致。
- **规则比对**（写进 `verify_flows.py`）：页面内嵌的 `global_rules` 与五类规则，与 `运营自检/checklist.json` 逐字段比对，不一致直接判失败。当前：5 类全部一致。

**为什么之前没这么做：** 我给的顾虑是「两套实现会漂移」。这个顾虑本身成立，但解法不是不做，而是**加比对把漂移变成会报错的失败**。因为怕漂移而留一道多余的人工序，是把风险转嫁给使用者。

**自检工具本体没动**，`跑自检.py` 也保留——批量跑或接 CI 时它更合适。

## 八、向旧版借结构（v3.6）

**反馈：** 「感觉这个旧 AI协作流程引导器.html 很多地方做的还挺有条理的，你新做的还没那么有条理呢。」

**先把两版的骨架逐块对比了一遍**（数一级块的种类与数量）：旧版主面板里是 **5 个等构的步骤块**，每块都是「标题 ＋ 一行 hint ＋ 内容」，节奏完全一致，所以看着有条理；新版主视图是泳道图（这点比旧版强），但页面整体是 **8 个长得各不相同的块竖着堆**（切换按钮／数字卡／现状／图例／泳道图／抽屉／自检／导出），没有统一的骨架，这就是「条理性不足」的实锤。

**旧版三个结构优点，逐一搬过来（新版功能一个不减）：**

| 旧版优点 | 新版原来的问题 | 改法 |
| --- | --- | --- |
| 左栏固定任务列表，选任务的上下文永远可见 | 任务按钮在页顶，滚到下面就不知道自己在做哪个任务 | 恢复左右两栏：左栏 sticky，放任务切换＋进度条＋关键数字＋图例；右栏放主内容。窄屏自动叠回单列 |
| 每个步骤块都有一行 hint（这一步干嘛） | 抽屉里是字段行，缺一句锚点，读了半天不知道这步在干嘛 | 抽屉标题下加「这一步要达成什么」（取自每步的 goal 字段） |
| 打勾进度条常驻（0/N） | 打勾只在图上标"已完成"，没有汇总 | 左栏加进度条，打勾实时更新 n/N |

**同时明确一点：** 旧版有条理的是**组织方式**，不是内容——它的五步是固定框架、没有分工与交接，这正是当初不复用它的原因。这次借的是**骨架**（两栏、等构步骤、进度条），**内容仍是新版的数据**（泳道图、自动化档位、页面内自检引擎、RACI、行业检查项归位）。

## 九、去掉开发痕迹（v3.7）

**反馈：** 「抽屉里全是字段行，没有锚点……乱七八糟的，AI 开发痕迹太重了，没有用的欲望！」

**这条指出了比排版更深的一层：前面几版我把"数据库记录"当成了"给人看的界面"。** 抽屉里是「机器｜xxx」「人｜xxx」「交接｜xxx」「产出｜xxx」这样的键值行，配上胶囊和边框——那是开发调试时看数据的样式，不是一个人写给另一个人看的说明。术语也是开发腔：自动化档位、例外制、人复核、RACI，这些词对写它的人自然，对用它的人是门槛。

**改动：**

1. **抽屉从字段行改成三句人话**（无边框、无标签行）：
   > **机器**按口径卡逐条打标，把跨类、写法含糊的挑出来标成待确认。
   > **你**要做的：只看被标为待确认的条目。
   > 这一步做完，手里有**打标表 ＋ 待确认清单**。
2. **术语全部改口语**：全自动→**机器全包**，例外制→**人只看例外**，人复核→**人过一遍**，人决策→**人拍板**。泳道图框下角、抽屉、图例、数字卡全部同步。
3. **图例改成人话**：「上面一排是机器做的」「下面一排是人做的」「箭头＝交给下一手」「框下角＝这一步谁出手」。
4. **数字卡标签**：步常规路径无需人工→**步不用人盯**；步仍需人参与→**步要人出手**。
5. **自检管道去掉开发腔**：删掉「流程产出」这个重复框，标签从「按类型自检／跑这些模块」改成「查什么／查哪些」。
6. 结构化的内容（RACI 四格、判定依据、出处、出错处置的 if-then）**没有删**，全部留在「更多」折叠里——那是给要追溯的人看的，不该挡在第一屏。

**一句根因：** 前几版我在给「评审的人」做界面（什么字段都要看得见、有依据），没有给「用它的人」做界面（三句话讲清楚我该干嘛）。两个受众都要服务，但**第一屏属于使用者**。

## 十一、按设计技能重做视觉（v3.15）

**反馈：** 「配色设计、UI/UX 太丑了，动画僵硬」「标识不清晰」。前面几轮我在配色与动效上都是凭感觉调的，这次按 `frontend-design` 技能走完整流程。

**定调**（技能要求先锁四问）：给运营同学在做重复任务时用；方向选**工业实用**（仪表盘密度、等宽数字、发丝线、状态色）；约束是**本地单文件、不能依赖网络字体**；记忆点是「两栏泳道图 ＋ 等宽数字 ＋ 发丝线」的值班台观感。

**做了什么：**

1. **整块样式重写**，不再零敲碎打改。令牌集中在 `:root`（颜色／字阶／间距／圆角／阴影／动效时长）。

4. **动效重做**：入场序列（左右两栏各 5 组、错峰 70ms）、悬停抬升 1px、切换步骤时抽屉淡入上移、进度条与按钮过渡统一到 `--ease`；系统「减少动效」时全部关闭。
5. **标识**：泳道标签加左侧色条并加大；**介入标签从挤在节点旁边挪到两条泳道之间的专用带，并按介入方取色**（青色＝人介入、琥珀＝机器介入）；标题加左侧强调竖条。
6. **窄屏**：左栏压紧、隐去与图上重复的图例；泳道图保持可读尺寸并横向可拖。

**过程中修掉的三处真问题**（都是截图看出来的，不是想出来的）：

- 入场动画用了 `animation-fill-mode:both`，无头截图在动画跑完前拍摄，页面看起来是空的 —— 这是截图时序，但也提醒我首次绘制前内容不可见；实测浏览器里 400ms 内完成入场。
- 窄屏试过把左栏压成两列网格，结果标签和内容被拆到不同列（正是「标识不清晰」），改回单列。
- 窄屏媒体查询写在组件定义之前，被后面的基础样式覆盖 —— 挪到样式表末尾才对。

**另外修掉一个校验误报：** `打包转发版.py` 原用裸 `sk-` 判断是否含密钥，把 smoke 测试里解析密钥的代码片段误判成密钥泄漏；改为按「sk- 加 20 位以上」的真实密钥特征匹配。

## 十二、改名与补自动化（v3.18）

**两条反馈**：一，「已带密钥」这名字不好，问「游戏运营部分场景的人机协作工具怎么样」；二，「自动化好像挺一般，全部都要靠手点击」。

### 改名

- `人机协作流程引导器.html` → **`运营场景人机协作流程工具.html`**（不含密钥）
- `人机协作流程引导器-已带密钥.html` → **`运营场景人机协作流程工具-本机版.html`**（含密钥）

**命名上做了一个判断：把默认的、干净的名字给可转发的那份。** 带密钥的加「-本机版」后缀。理由是转发场景里人容易顺手发文件名最"正常"的那个，让安全的那份占住默认位置，发错的概率最低。

**改名带出一个必须同步修的风险**：打包脚本原来靠文件名里有没有"密钥"二字来排除带密钥文件；新名字里没有这两个字，**照原样打就会把带密钥的那份装进转发包**。已同步把"本机版"加进排除名单，并保留"扫包内文本查密钥特征"作为第二道保险。

### 补自动化

| 原来 | 现在 |
| --- | --- |
| 选文件 → 跑自检 → 让 AI 再读一遍 → 手动勾步骤 → 导出（五次点击） | **一键跑完**：点一次，连跑规则检查＋AI＋出流程单，并自动勾掉「交付前自检」 |
| 得先点「选文件」再选路径 | **拖拽即跑**：把稿子拖到页面任意位置，自动载入并开跑 |
| 换任务、刷新后打勾全丢 | **状态记忆**：记住上次任务与打勾进度 |

**只自动勾「交付前自检」这一步**，其余步骤不代勾——工具确实做了自检，但采集、打标、成文这些它没做，只是假定你在别处做了，代勾会把进度变成假的。

**刻意保留手动的四类**：定口径、风险定级、写结论、签字放行。要么是判断、要么是责任，机器代不了。

## v3.19　凭据随页面走，拿到就能用

### 为什么改

上一版分成两个文件：一个不含密钥（可转发，但要自己填一次密钥），一个含密钥（自己用，不能转发）。用户反馈：**「怎么还是要输密钥，转发给别人的应该是不显示的，直接可以用的！」**

用户先问能否写进环境变量。这里要说清一个技术事实：网页脚本读不到操作系统环境变量（浏览器安全限制），而且即便读得到，换成「外部文件存密钥」也只是换位置，密钥仍然要跟着文件发出去，安全性没有任何变化。**真正的分界线只有一条：密钥要不要离开你的电脑。** 用户确认「反正是免费的密钥，无所谓，只是不要太明显就好」，据此定了做法。

### 怎么改

**一个文件，凭据编在里面。** 源码里不写明文，改成逐字节异或后的数字串：

```js
var LLM_KEY_ENC = [数字, 数字, ...];   // 明文搜不到
var LLM_KEY_SALT = 137;
function llmUnwrap(){                  // 运行时拼回来
  var s = '';
  for (var i = 0; i < LLM_KEY_ENC.length; i++) {
    var v = LLM_KEY_ENC[i] ^ ((LLM_KEY_SALT + i * 29) & 255);
    if (v <= 0) break;
    s += String.fromCharCode(v);
  }
  return s;
}
```

配套改了三处：

| 改动 | 原来 | 现在 |
| --- | --- | --- |
| 界面 | 「首次用要先填一次密钥」＋密码框＋换密钥链接 | 只剩「让 AI 再读一遍」一个按钮，旁边空着 |
| 取密钥 | `LLM_KEY_BUILTIN`（明文变量） | `llmUnwrap()` 解码 |
| 模型名 | 藏在 localStorage 配置里 | 独立成 `llmModel()`，无配置时用默认值 |

`注入密钥.py` 整个重写：不再生成第二个文件，改为**就地**改写主文件的编码位；新增 `--清空` 用于产出一份不含凭据的公开留底。删掉了已无用途的 `-本机版.html`。

### 顺手清掉的问题（校验时发现，不是用户提的）

打包清单里混进了**两个 0 字节文件**，文件名是一整句中文——是此前写文档时用 `>` 造成的（bash 把它当成输出重定向，把句子变成了文件名）。已删除，包内文件从 13 个降到 11 个。

### 边界（明确写进 README，不藏着）

编码**不是加密**。懂技术的人花几分钟能还原出来。所以：自己用、发给面试官看、发给同事试都没问题；要公开发布（挂服务器、传公开仓库）先跑 `--清空`；凭据是免费额度，被刷爆了重新申一把再跑一次注入脚本就行。

## 十三、v3.22：把「AI 那层为什么每次不一样」查清并落到界面上

用户在页面上跑完之后问了一句：**「都是用的一样的填写模板，怎么每次发现问题都不同？」**

这不是配置问题，是这层机制的性质。所以先实测，再改。

### 实测数据

| 对象 | 跑法 | 结果 |
| --- | --- | --- |
| 规则引擎 | 同一份稿连跑 3 次 | 3 次都是 0 项，**完全一致** |
| 大模型 | 同一份稿、同一提示词连跑 9 次 | **5 次报出问题，4 次答「无」** |

规则引擎的判定条件是写死的，同输入必然同输出。大模型的输出本身带采样随机性，同一输入每次不同。温度从 0.3 降到 0 能减少但不能消除——**降为 0 之后实测仍会出现有时报有时不报**。

### 改了三处

1. **提示词收紧。** 原来只说「找语义层问题」，现在给四条准入标准（结论夸大到数据撑不住、对外承诺超过内部实际动作、同一件事多处口径打架、分类标签与问题根因对不上），加五条一律不提（文风措辞、格式排版、觉得「还能更好」但没错、已标明是示例或占位符、自己不确定的猜测），收尾一句「宁少勿滥」。**收窄判定范围是为了让「报」这个动作更稳定**——范围越模糊，每次注意力落在哪里就越随机。
2. **温度 0.3 → 0**，减少采样随机性。
3. **结果面板答「无」时的提示语改了。** 原来写「大模型看过了，未提出语义层问题」，给人「检查过、没问题」的错觉。改成「这一遍没提出语义层问题」，并补一句「AI 这一层是启发式的：同一个问题，多跑一次结果可能不同。它没提，不等于真没有」。

### 落定的口径

**大模型这一层是「多一双眼睛」，不是「一道关」。**

- 它报的有问题 → 自己判断成不成立（第三轮 5 条里就有 1 条是没读到上下文的误报）
- 它答没有 → 不代表真没有，人的通读不能省
- 规则引擎报不过 → 那就是不过，这个能当关卡

这两层的性质不同，用法就不该一样。已同步写进 `README.md`（AI 辅助判读节）、`交付说明-两份工具怎么配合.md`（新增两工具性质对照表）、`模板/试跑记录.md`（新增第四轮）。

## 十四、v3.23：把 AI 从「末尾查错」挪回「前面干活」

用户看完 v3.22 的说明后指出：**「大模型在这里面的作用应当是添砖加瓦才对，你开发不太行啊问题挺大的。」**

把两条流程的全部 13 步拉出来，逐步看 AI 的实际角色：

| | 玩家反馈日报 | 活动上线前检查 |
| --- | --- | --- |

| 人当 R | 2 步 | 2 步 |
| 逐条数 AI 动作 | 采集规范化、分类打标、紧急项初筛、成文、自检 | 对齐清单、逐项对照、走查、生成预案骨架、汇总放行项、上线回补 |

**产出型 8 步、查验型 2 步，13 步里 12 步都有 AI 的活。** 流程设计层面上 AI 一直是主力，干的是逐条打标、按模板成文、逐项比对这类执行工作。

**但页面里能真跑的只有 2 个按钮（规则检查、让 AI 再读一遍），而且都是查错。** 也就是说：

- 文档层面：AI 承担 12 步 ✅
- 可运行层面：只有末尾那两步能一键跑 ❌

这不是技术限制——打标和成文是 LLM 最擅长的，接口早就接通了。**是我把开发力气放错了地方：先做了收尾的查错，没做主线的干活。** 用户说的「问题挺大」指的就是这个。

### 补了什么

页面底部从「只有自检」扩成三步，顺序即流程第 3、5、6 步的顺序：

1. **打标**（新增）：贴原始反馈 → 出一张表（反馈类型／归属模块／影响范围／紧急度／可复现／置信度／备选归属）。提示词里写死「只要你不确定，就写低，并在最后一列写上另一种可能的归属」——**拿不准的标成待确认，不许硬猜**。人先看被标出来的那几行，其余抽看。
2. **成文**（新增）：按打标结果生成日报初稿。必含栏目缺的标「（待补）」，**结论与建议故意留空**——流程第 5 步写明了这一步只填结构与事实，结论是人的活。初稿可一键填进第三步的自检框。
3. **自检**（原有）：规则引擎五模块。

原先那个「让 AI 再读一遍」保留在原位，但**定位写清了**：打标与成文是出活，它是查错，两者不是一回事。

## 二十一、v3.30：流程扩到 11 项，边界两侧都画出来了

### 新增第六个交付物类型

现有五类装不下「发放前核对表」——它不是分析报告（report），也不是配置核对清单（config_checklist，那份查的是弹窗、入口、参数、开关服）。所以按产出物形态补了一类 `reward_check`，必含栏目是：应发口径、应发名单、差异项、防刷、核对人、签发。

**加类型要改两处并逐字段对齐**：`运营自检/checklist.json` 与页面的 `meta.check_engine.types`，校验会比对 `name`、`required_sections`、`forbidden_wording`、`soft_wording` 四个字段。页面侧只有五个字段（`source_note` 与 `industry_sources` 是 checklist 侧才有），所以两边不能图省事直接拷同一份。

顺带被校验拦了一次：这个类型的规则里带禁用词，那 B 模块就该适用，但我在 `selfcheck_rules` 里漏了 B。**校验是照着 `forbidden_wording` 反推的**，拦得对。

### 奖励发放那条：第 5 步和第 6 步之间是最硬的一道门

岗位分析里有一条硬约束：

> 给了用户的，不能拿回来。

所以整条流程的定位是**「发放前把差异找出来」，不是「发完再修正」**：

- **第 5 步「发放前核对与签发」**把应发口径、名单、差异项、防刷结论、发放方式全部列齐，逐条核完签字
- **第 6 步「执行发放」**才动手，而且这一步的出错处置写成：发错道具或数量 → 立刻上报，**只能按补偿处理，不能回收**
- **第 7 步「到账核对与补发建议」**特意区分两种情况：**漏发可以补，多发只记录不回收**；并写明要判断是「名单算漏」还是「发放失败」——两者改法不同

### 卖点提炼那一步留住了那句话

岗位分析引用的公开流程原话是：**「并不是玩家的反馈建议就一定要听」**。所以第 4 步不只是「定主推哪几条」，还明确要求**对社区喊得凶但不该跟的，写明为什么不跟**——取舍要留依据，否则下一次还得重新辩一遍。

### 方案设计那一步防的是流程倒置

3.6 点出一个常见毛病：**很多团队容易陷入「先想奖励再想规则」，导致上线后数据难以归因**。所以第 1 步先定唯一核心指标（方案顶部那一行），**第 4 步专门查奖励与规则有没有倒置**，同时过一遍 3.4 的奖励两条原则。

### 最后一项没画，原因写在 README

十二项里唯一没画的是**「福利规划与付费点设计」**。它判为「保留人工」，理由是那两条原则**一条是商业权衡、一条是信誉承诺，都不是机器能算的**。

关键在于它和另两项「保留人工」的任务**不一样**：版本卖点提炼、活动方案设计至少还有「AI 供素材」这一层，机器泳道上有节点；这一项**连素材都不该由 AI 供**，画不出两条泳道。

**工具在能交的地方画流程，同时在 README 里说明有一项完全不该交给 AI——这两件事放在一起，边界才是完整的。** 只画能交的，看不出线画在哪；只说不画，也说不出为什么。

## 二十二、把「没画的那一项」做成数据（v3.31）

### 起因：结论只活在文档里

十二项岗位任务画了十一项，剩「福利规划与付费点设计」。上一轮的处理是**只在 README 里写一段说明**。两个问题：

1. **打开工具看不出这件事。** 工具本体只呈现了画出来的十一项，第十一项之后的空白没有任何交代。
2. **覆盖率报告里那行「未覆盖」是悬挂的。** 它只是被列出来，不代表已经处理过——「没画」和「忘了画」在报告里长得一模一样。

### 为什么不硬凑 12 / 12

动手前查了三处结构约束，结论是这一项画不进去**不是技术问题，而是「每一步都有跨泳道交接」是这个工具的不变量**：

| 约束 | 位置 | 说明 |
| --- | --- | --- |
| 四档里没有「不参与」 | `meta.tiers` + `AUTO_BY_TIER` | 从「可以完全替代」到「不能替代」，档四只能填「人决策」；每一档都假定机器有活，只是活多活少 |
| 每一步的 `other` 与 `C` 必填 | `verify_flows.py` 2c | 必须标出「另一侧泳道」的协作方；全人任务里这一侧没有活，无法诚实填充 |
| 档三/档四硬绑在人泳道 | `verify_flows.py` 2c | 跨泳道箭头的前提就是「另一侧有人接」 |

放宽其中任何一条，打松的都是已经立住的东西。**所以不改规则，改的是「怎么把这件事说清楚」。**

### 改动三处

**一、数据**：`meta.job_coverage`（含 `total` 与 `excluded`）。选这个形态是因为工具里本来就有同类机制——`industry_items` 那份行业检查清单早就在用 `scope: "in"/"out"`，「范围外写明理由」不是新造的概念。

**二、页面**：「判定依据与出处」折叠区新增一节「岗位任务覆盖」，写明共十二项、画了十一项、另有哪一项判定不画以及理由与出处。这一区本来就是讲判定依据与边界的地方。

**三、校验**：`verify_flows.py` 新增一组断言——
- `total` 必须等于岗位清单的项数
- 每项必须有 `line` / `task` / `judgment` / `reason` / `why_not_drawn` / `from`
- `task` 必须在岗位清单内、`line` 必须是两条线之一
- **每一项岗位任务要么在 `maps_to` 里、要么在不画登记里，两边加起来正好十二项**；悬挂或重复认领都直接报错

覆盖率那行也从「覆盖 11 / 12 项」改成「覆盖 11 / 12 项；另 1 项登记为不画（理由已写明）」。

### 验证：新断言做了负向测试

只跑一次通过，只能证明它**不响**；要证明它**会响**，得人为破坏一次。三组破坏，跑完自动还原：

| 破坏 | 期望 | 实际 |
| --- | --- | --- |
| `total` 从 12 改成 13 | 报出 | **报出「job_coverage.total 写的是 13，岗位清单是 12 项」** |
| 任务名改成清单里没有的 | 报出两条（不在清单内 ＋ 悬挂） | **两条都报出** |
| 删掉 `why_not_drawn` | 报出 | **报出「缺字段 why_not_drawn」** |

3 / 3 被拦住；还原后内容与原文一致、校验退出码 0。

冒烟测试新增 3 条断言：渲染结果里必须有「岗位任务覆盖」和那句判定理由，数据里登记不能为空。

## 二十三、动画、任务分派、全程跑（v3.32）

### 起因：用户连着发现三个问题

1. **等待提示是静态文字**，别人用会以为卡死了
2. **AI 那一段写死了「玩家反馈日报」**，点别的任务（活动上线前检查、版本更新公告发布……）看到的还是同一套界面。查证属实：标题、输入框提示、按钮、提示词全部写死，被无差别套到了全部 11 个任务
3. **「一键跑完」名不副实**，只串了自检与 AI 读；打标两步、成文都不在里面。用户的原话是「这几个完全可以一个按钮全部跑完，同时能看得到进度、可以随时打断」

外加一条：AI 审读只给「问题」，不给「改法」，模型还爱输出大段思维链。

### 逐项改法

**一、等待动画。** 换成三点跳动 ＋ 一条来回跑的进度条，抽成 `ld(text)`，四处等待文案共用。

**二、按任务类型分派。** 依据是 flows 数据里现成的 `selfcheck.type_key` 与 `deliverable`：

| 类型 | 任务 | 走哪几段 |
| --- | --- | --- |
| 整理型（feedback_table / report） | 玩家反馈日报、报告生成、活动效果分析等 7 个 | 材料 → 合并去重 → 逐条归类 → 出初稿 |
| 核稿型（announcement / launch_check / reward_check） | 版本更新公告发布、活动上线前检查、奖励核对等 4 个 | 直接贴成稿 → 自检 → AI 审读 |

- 新增 `aiSpec(t)` 统一算这层配置，文案按交付物动态取，不再写死
- **玩家反馈日报那套提示词是 v3.24 花六轮校准出来的，一个字没动**；report 类另起一套简化口径（`TAG_R1`/`TAG_R2`）

**三、审读结果三段结构化。** 提示词要求每条按「条目／问题／改法」三行输出，并明令禁止输出思考过程。解析用 `parseLlm()`，渲染出「原文（长了可展开）／问题／改法」三栏，底部给「按这些改法重写一版」——那条会带着改法再调一次，输出新初稿填回框里。

**四、全程跑 ＋ 进度 ＋ 可中断。** 新增 `runPipeline()`：整理型 6 步、核稿型 2 步，顶部进度条显示「第 n / 6 步 ＋ 当前步骤 ＋ 停下按钮」。中断用 `AbortController`，`llmP()` 是带信号的 Promise 版调用。**复核点按用户选择保留**：跑到「合并复核」停下，给「继续」与「跳过复核，一路跑完」两个出口。分步按钮全部保留——复核点是人机分工的落点。

### 踩的坑（我自己造成的）

**把 `MOD_SHORT`、`LLM_DEF`、密钥常量一起切掉了。** 脚本里找函数结束位置用的是「下一个 function」，而 `renderLink` 后面紧跟的是 `var MOD_SHORT`，于是连带切掉了四个定义，密钥也没了。动手前备了份，恢复后把切法改成**花括号配平**，之后每步都加关键定义自检。

**错误提示一律写进整理区** —— 边界测试暴露的：「初稿框是空的」跑到整理区，人得满页找。`stepFail` 改成可指定区域。

**测试断言把模型特性当产品缺陷** —— 真调用测试里断言「模型必须报出问题」，而它本来就有答「无」的概率。改成只压确定性部分。

### 测试（本轮起，交付前必须五套全过）

| 测试 | 结果 |
| --- | --- |
| 冒烟：主路径与跨引擎比对 | 通过（四样例 15/7/9/5 两边一致） |
| 边界与错误路径（新增，8 组） | 通过 |
| 真调用端到端（新增） | 通过（9.7 秒返回 5 条完整三段条目） |
| 流程校验 | 通过（11/12 ＋ 1 项登记，74 步） |
| 规则引擎评测 | 通过（39/39，100%，零误报） |

**负向测试 4 / 4**：人为破坏四处（错分派、去动画、不复位状态、丢区域参数），全部报出对应失败项，还原后退出码回到 0。

## 二十四、v3.33 泳道图的格式问题（2026-09-23，用户看图指出）

前面所有测试都查不出这类问题：它们看的是代码行为与数据，看不到画出来的东西。这次是用户把图截来，才暴露出来。

### 四类现象，同一条病根

1. **标题溢出卡片**：图的总宽写死 860，再按步数均分列宽。8 步时卡片只有 74.5px，而换行按固定 7 字切（中文字 12.5px 字号下是 87.5px）——必然冲破卡片边界
2. **标题第二行与底部小字叠在一起**：第二行 y 在 by+56，底部小字在 by+54，同一位置
3. **断词难看**：「入库与模板化判断」切成「入库与模板化判」+「断」，第二行只有一个字
4. **CSS 把图拉大**：`width:100%` 让 860 的 viewBox 撑满容器，字同比放大，溢出更明显

### 改法

| 改什么 | 怎么改 |
| --- | --- |
| 图的宽度 | 列宽固定 150，总宽按步数算：6 步 988、7 步 1138、8 步 1288 |
| 每行几个字 | 按卡片实际可用宽度算，不写死 7 或 8 |
| 断行位置 | 切点前三个字里有连词或标点时切到它后面；第二行只剩一个字时从第一行挪一个字过来 |
| 卡片高度 | 62 → 92，四行各就各位（第几步 18、标题行一 43、标题行二 61、底部小字 82） |
| 图被放大 | 加 `max-width` 等于图宽，容器更宽也不放大 |
| 底部提示 | 去掉「图可左右拖」，宽度已经自适应 |

### 检查做成了一条命令

`python test_layout.py`：渲染 11 个任务 → 导出可测量的 HTML → headless 浏览器量**真实文字包围盒** → 判定四类问题（卡片跑出泳道、文字没有完整落在卡片内、同卡片两行相叠、介入标签横向压到一起）。11 / 11 通过。

**为什么是 Python**：这台机器上 node 被禁止派生任何子进程，`spawnSync`、`execFileSync`、`execSync` 连 `cmd.exe` 都 EBUSY（换系统 node 也一样），而调浏览器就要派生子进程。所以拆开——`render_flows.js` 只渲染不派生，`test_layout.py` 调 Chrome 并判定。

**两个坑**：① 不能给 `global.URL` 赋普通对象，node 的文件代理要用它做 `instanceof`，覆盖后 `readFileSync` 全挂——冒烟、边界、布局三个测试同时报错；② 负向测试第一版没有兜底还原，脚本崩在还原前，把破坏态文件留了下来，导致下一轮读到坏文件、结论全错。现已加自愈备份与前置校验。

### 检查脚本自己的两个 bug（负向测试抓出来的）

1. **字段名写错**：存进去叫 `h:` 读的是 `.height`，差值恒为 NaN，`NaN < 1.5` 永远为假——**行间距这一段从来没生效过**，等于白写
2. **归属条件只按 y 判断**：同一泳道相邻卡片的文字被当成一张卡片的行，凭空报「相叠」

修完并固化一条写法：**阈值判定写成 `!(值 >= 阈值)` 而不是 `值 < 阈值`**。字段名再写错，NaN 会当场报出来，而不是静默通过。

### 也修了冒烟测试的一条脆弱断言

原来断言「泳道图里有标题的前 7 个字」，把断言绑死在断行位置上。改成把 SVG 里所有文字拼起来找完整标题，这样断行规则怎么调都不会误报。
