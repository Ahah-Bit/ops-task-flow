# docs 目录说明

| 文件 | 内容 | 原本在哪 |
| --- | --- | --- |
| `迭代记录-25章.md` | 从设计期到 v3.33 的完整迭代记录，25 章，含被打回来的决策与改法 | `人机协作流程工具/迭代记录.md` |
| `六轮校准总结.md` | 六轮真实材料校准的结论 | `人机协作流程工具/校准材料/校准总结.md` |
| `校准过程原始记录/` | 六轮打标结果与分步脚本，六轮原始留档 | `人机协作流程工具/工程文件留底/校准过程原始记录/` |
| `测试报告-v3.32.md` | 五套测试与布局检查的原始报告 | `人机协作流程工具/测试报告-v3.32.md` |
| `测试报告.md` | 本轮测试索引，含稳定性实测与证据指向 | 本轮整理 |
| `评测报告.md` | 一条命令出的四个数与评测层补项 | `公开版/评测报告.md` |
| `调研与出处.md` | 行业框架逐条出处与年份 | `人机协作流程工具/调研与出处.md` |
| `工具说明.md` | 页面使用说明与设计定调 | `人机协作流程工具/README.md` |
| `怎么复跑测试.md` | 六套测试的运行条件与顺序 | 本轮整理 |
| `仓库检查清单.md` | 公开前逐项扫描结果 | 由 `检查仓库.py` 生成 |

除标注「本轮整理」的两份索引外，其余都是从本地工程原样复制，没有改写。迭代史与校准过程一并公开，是为了让设计决策的时间线可查。

`docs/评测报告.md` 是从本地工程那次运行复制来的，仓库根的 `评测报告.md` 是在公开仓库里重跑 `eval_report.py` 生成的。两处四个数相同，差别只在提示词指纹：本地那份取自带凭据的工具原件，仓库这份取自不含凭据的公开版页面，报告第四节「指纹取自」写明了用的是哪一份。
