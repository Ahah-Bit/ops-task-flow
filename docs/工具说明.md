# 运营任务的人机协作流程

**岗位：产品运营 & 活动运营（AI 方向）· 崩坏：星穹铁道**

任务刚接到手上时用的东西。它回答五件事：这条任务分几步、每一步 AI 具体做什么、人做什么、在哪里交接、交出来的产物是什么、哪一步出错该怎么办。

---

## 设计定调（为什么长这样）

按 `frontend-design` 技能的四问锁定，只选一个方向，不混搭：

- **给谁用**：运营同学在做一件重复任务时打开它，需要一眼看清「分几步、机器做什么、人做什么、打勾到哪了」。
- **方向**：**工业实用（Industrial / utilitarian）**——仪表盘密度、等宽数字、发丝边框、状态色体系。不追求氛围感，追求可读与可核对。
- **字体**：数字与标签用**等宽**（Cascadia Mono / Consolas），中文正文用思源黑体 / 微软雅黑。等宽数字是这套界面的辨识点，也是对齐、编号、进度能一眼扫完的原因。**本地文件不依赖任何网络字体**，断网也长这样。
- **配色**：暖中性纸面主色（约 60%）、发丝线做结构（约 30%）、**单一琥珀色作强调**（约 10%，只给关键动作）。机器／人／交接三个颜色只承担数据编码，不做装饰；颜色之外一律配文字标签，不靠颜色表达含义。
- **记忆点**：两栏泳道图 ＋ 等宽数字 ＋ 发丝线，构成的「值班台」观感。
- **动效**：一次编排好的入场序列（左右两栏各 5 组，错峰 70ms），悬停抬升 1px，切换步骤时抽屉内容淡入上移；系统开启「减少动效」时全部关闭。
- **可访问性**：正文对比度 ≥ 4.5:1，`:focus-visible` 焦点圈可见，按钮可键盘触达。

**设计令牌集中在样式表顶部的 `:root`**，改色改字号只动那一处；脚本里读的是同一套令牌，不重复写死色值。

**反 AI 味自检**（技能给的 12 条）：展示字不用 Inter/Roboto/系统默认（改用等宽）✓；无白底紫渐变、有明确主色 ✓；首屏不是居中标题加三张特性卡 ✓；卡片不是一模一样的圆角加统一阴影（泳道图、数字行、抽屉各不相同）✓；图标不靠通用线性图标集凑数 ✓；文案无「赋能／新一代／释放潜力」✓；动效不是所有元素统一 300ms 淡入（有错峰与层级）✓；有氛围层（极淡工程网格 ＋ 左上暖光）✓；有辨识点 ✓；状态覆盖悬停／聚焦／选中／完成／空态／错误 ✓；对比度已按标准取值 ✓。

## 一、看一眼就知道怎么用

打开 `运营场景人机协作流程工具.html`。单文件，双击即用，不联网、不依赖任何环境。

页面是**左右两栏**（窄屏自动叠成单列）：

**左栏固定不动**，滚到哪都在：任务类型切换、本单进度条（打勾 n/N）、四个关键数字（几步流程／几步常规路径无需人工／几步仍需人参与／几处交接点）、怎么读这张图。

**自动化到哪一步：**

- **一键跑完**：粘上初稿点一次，连跑规则检查 ＋ AI 再读 ＋ 出流程单，并自动勾掉「交付前自检」这一步（只有这一步是工具真做的，代勾其他步会失真）
- **拖拽即跑**：把 `.md`／`.txt` 直接拖到页面上，自动载入并开跑，不用先点「选文件」
- **状态记忆**：记住上次选的任务与打勾进度，下次打开接着用

**刻意保留手动的地方**：定口径、风险定级、写结论、签字放行这四类。它们要么是判断，要么是责任，机器代不了——这也是流程里 A（最终责任人）必须是人那一条的落地。

**一个文件，拿到就能用：**

`运营场景人机协作流程工具.html` 里带着访问凭据，双击打开，点「让 AI 再读一遍」直接出结果，**界面上没有输入框、也不提示填任何东西**。把这个文件发给别人，对方同样双击即用。

凭据在源码里不是明文，是一串编码过的数字（运行时拼回来）。搜 `sk-` 搜不到完整密钥，右键看源码不会一眼看到。

**要说清楚的边界**：这是「让人不能一眼看到」，不是加密。懂技术的人花几分钟能还原出来。所以——

- 自己用、发给面试官看、发给同事试：都没问题
- 要公开发布到网上（挂服务器、传公开仓库）：先跑 `python 注入密钥.py --清空`，产出一份不含凭据的留底
- 凭据是免费额度，万一被刷爆了，重新申一把再跑一次 `python 注入密钥.py` 就行

**右栏从上到下**：

1. **泳道图**（主视图）：机器泳道在上、人泳道在下，每个步骤落在执行方所在的泳道，跨泳道箭头＝交接，虚线连的是另一侧在这一步的介入；框下角标自动化档位（全自动／例外制／人复核／人决策）。点任意节点看细节。
2. **细节抽屉**：默认只显示四行——机器做什么、人做什么、交接方向、产出物，标题下有一句"这一步要达成什么"。其余（交接说明、机器要的信息、人要拍什么板、出错怎么办、判定依据、出处、RACI）收在「更多」里，点开才看。
3. **交付前自检**（见第三节）与**导出协作流程单**。

### 导出

「本次的具体情况」里贴上这次的要求原文或特殊之处，带关键词会给出例外提示（例如提到"排行榜""抽奖"就提示风险排查不能跳）。走完导出《协作流程单》，可直接粘给同事，或附在这次任务的说明里。

### 为什么有一项没有画进来

十二项里唯一没画的是**「福利规划与付费点设计」**。岗位分析对它的判定是「保留人工」，理由写在 3.4 的两条原则里：

> 一条是商业权衡，一条是信誉承诺，都不是机器能算的。

其他判为「保留人工」的任务（版本卖点提炼、活动方案设计）**至少还有「AI 供素材」这一层**，机器泳道上有节点，画得出来。这一项**连素材都不该由 AI 供**，所以画不出两条泳道。

**工具在能交的地方画流程，同时说明有一项完全不该交给 AI——这两件事放在一起，边界才是完整的。** 只画能交的，看不出线画在哪；只说不画，也说不出为什么。

**这一条不只写在这份文档里。** 工具页的「判定依据与出处」折叠区里也列了它；`meta.job_coverage` 是这条登记的存放处，`verify_flows.py` 会核对「画了的 ＋ 登记不画的 ＝ 岗位清单全部」——出现**悬挂**（既没画也没登记）或**重复认领**（既画了又登记为不画）都直接报错。

## 三、和自检工具是怎么接上的

**两个工具是一条链，不是两个并列的东西：**

```
接到任务 →〔本工具〕定怎么走 → 按流程执行 →〔自检工具〕交付前逐项核 → 交出去
```

自检工具已经存在（`../运营自检/`，六模块、评测 39/39）。本工具不重做它，而是**把接口对齐清楚**：

**每类任务绑定自检工具里的真实交付物类型。**

| 本工具的任务 | 自检工具里的类型 | 会跑的模块 |
| --- | --- | --- |
| 玩家反馈日报 | `feedback_table` 玩家反馈分类表 | A 数据、C 结构、D 一致性、E 来源 |
| 活动上线前检查 | `launch_check` 版本上线自检（另跑 `config_checklist` 配置核对清单） | A 数据、C 结构、D 一致性、E 来源 |

**B 表述检查在该两类交付物上被划掉**：这两类的规则里没有禁用词与软性词，跑了也是空转。这不是省略，是省掉空转。

**必含栏目提前列出来，让检查前移。** 页面把该类交付物的必含栏目直接列出来（例如反馈日报的「来源渠道、分类、可复现、影响范围」），写的时候就对齐，而不是等交出去才被机器拦下。

**自检已经集成在本页，粘上初稿点一下就出报告。** 不用开终端，也不用改任何配置文件。

页面底部这一区按流程的顺序分成三步，**前三步顺序就是流程第 3、5、6 步的顺序**：

| 区 | 对应流程哪一步 | AI 干什么 | 人干什么 |
| --- | --- | --- | --- |
| 第一步 把原始反馈变成表 | 第 1、3 步（定口径、分类打标） | 分两次调用：先合并去重、剔除纯发泄，再逐条打标 | 核合并结果，再看全表 |
| 第二步 出日报初稿 | 第 5 步（成文） | 按必含栏目生成初稿，只填结构与事实，每个数字标出处 | 补结论与建议 |
| 第三步 交付前自检 | 第 6 步（自检） | 跑规则引擎六模块，出问题清单 | 只改报出来的问题 |

**顺序不能反。** 先打标再成文，最后才自检——AI 是**先干活、后查错**，不是只站在末尾当质检。

### 第一步：打标（AI 出的活，分两次调用）

把各渠道导出的原始反馈整段贴进去，不用先整理格式。点「跑打标」，它分两步走：

**第一步　合并与过滤。** 说的是同一件事的合成一条，纯发泄、说不出具体问题的剔掉。判据写死的是「**判断标准是有没有可落地的事实，不是语气好不好**」——语气激烈但指出了具体问题的要留。输出一份清单，人先核这一步的合并对不对，不对可以退回重跑。

**第二步　打标。** 拿合并后的清单逐条给：反馈类型、归属模块、影响范围、紧急度、可复现、置信度、备选归属。置信度写低时要求给出另一种可能的归属，不许硬猜。

**为什么要拆成两次调用——这是实测出来的，不是设计偏好。** 把「合并／过滤／打标」塞进同一段提示词，实测四轮，每轮稳定执行的那几条都不一样，而且新加的指令会挤掉旧的：第四轮只加了一句「已修复的标低」，紧急度立刻对了，可合并、过滤、置信度三条同时崩掉（32 条一条没合、剔除 0 条、置信度全给「高」）。拆成两次调用后，同一份 32 条材料，所有项同时正常。完整对照见 `校准材料/校准总结.md`。

**这一层的产出要人过一眼，不能只看标红的几条。** 实测它可能整轮不标待确认。它做得稳的是分类归到具体功能名、本地化类不会串到服务器问题、可复现栏能照抄原文条件；不稳的是合并的粗细程度（同一份材料，8 条到 16 条都出现过）。

### 第二步：成文（AI 出的活）

按打标结果生成日报初稿。必含栏目缺的会标「（待补）」，**结论与建议故意留空**——流程第 5 步写明了这一步「只填结构与事实，不写结论性判断」，结论是人的活。初稿可以直接填进第三步的自检框。

**统计数字不让模型算。** 页面先用代码解析打标结果，算出总条数、各反馈类型条数、各紧急度条数，再把结果作为已知事实写进提示词，让它直接引用。

这么改有实测依据：让模型自己数的时候，它会在同一段里写「共 4 条」却列出 5 个序号——第一版还把矛盾摊在稿子里（自带「修正统计」「请再次核对」），加了「不要输出核对过程」之后错误反而藏起来了。**能被枚举的交给机器算，这条线在成文这一环同样成立。**

成文之后仍有不稳：实测有一版漏了「可复现」这个必含栏目，还有一版把「高紧急度 1 条」写出了两个条目。前者被规则引擎拦了下来，后者目前没有关卡能拦——**所以初稿要人过一遍再看结论栏**。

### 第三步：自检

粘初稿，或点「选文件」直接读本地 `.md`／`.txt`；点「跑自检」出问题清单，格式与自检工具一致（严重度／行号／原文／问题／建议），末尾给「待处理项合计」。活动线还多一个按钮，同一份稿子再按配置类跑一遍。

六个模块（A 数据与出处／B 禁用表述／C 栏目覆盖／D 同一指标多值／E 引用可查性／F 数量与枚举是否对得上）按 `../运营自检/` 里的 Python 逻辑逐行移植，规则取自同一份 `checklist.json`。**两道锁防止两边算出不同的数**：`smoke_test.js` 拿四份样例做跨引擎比对（数必须一样），`verify_flows.py` 把内嵌规则与 `checklist.json` 逐字段比对（不一致直接失败）。

批量跑或接 CI 时仍可用命令行版：

```
python 跑自检.py <初稿路径> feedback_table
```

**注意：要检指定的文件，只能走 `跑自检.py`，不能直接给 `run_all.py` 传路径。** `run_all.py` 是用 subprocess 逐模块跑的，`checklist.json` 里的 `target` 传不到子进程，所以它会一直检自己目录下的默认样例——传参是无效的，而且不报错，很容易以为检过了。`跑自检.py` 走的是「复制到 `_run/`、改副本配置、在副本里跑」，**不改动 `运营自检/` 本体**。

（`运营自检/eval.py` 不受这个问题影响：它是同进程 import 各模块再调 `set_target()`，配置生效，所以评测报告的检出率是可信的。）

### 最后一步：让 AI 再读一遍（可选）

打标与成文是**出活**，这一步是**查错**，两者定位不同。规则引擎只能查**形式**（数字有没有出处、栏目齐不齐、同一指标是不是两个数），查不了**语义**（这句话会不会让玩家误解，「本地化缺失」被写成「跨服区」算不算错配）。自检块底部有一个「让 AI 再读一遍」按钮补这一层：

**这条边界是实跑测出来的，而且被修正过一次。** 最初把它描述成「查格式」，后来真有稿件把本地化问题写成「跨服区缺陷」，规则引擎那些模块一个都没报——因为它只认「这个数有没有出处」，不认「这个标签配不配得上这个问题的根因」。所以现在的说法是：**它管可枚举的形式，不管术语与语义是否自洽。**

- **点一下就出结果**，界面上没有设置表单、没有输入框、没有要你填的东西
- 访问凭据已经随页面一起走（编码存放，源码里搜不到明文），接口与模型也已预填好（Agnes AI，OpenAI 兼容）
- 大模型的意见与规则结果**分开展示、以规则为准**；免费模型的结论要自己核
- **它说不等于真没有。** 规则引擎是可复现的：同一份稿连跑三次，结果完全一样。大模型不是——同一份稿、同一段提示词，实测 9 次里 5 次报出问题、4 次答「无」。所以页面上给的提示语是「这一遍没提出语义层问题」，不是「没有问题」。**这一层定位是「多一双眼睛」，不是「一道关」。**
- **两层的可信度不是一个量级**：规则引擎在 4 份注入式样例上注入 38 项、检出 38 项（检出率 100%，误报 0），跑几次都是这个数；大模型那一层是补盲区用的，报出来的要判断，没报的还得自己看
- **换自己的凭据**：把新密钥存成 txt，跑一次 `python 注入密钥.py`，重新覆盖写入即可
- **产出一份公开可发的留底**：`python 注入密钥.py --清空`

**发给别人时**：直接把这个 HTML 发过去就行。要连模板一起发，跑一条命令——

```
python 打包转发版.py
```

它会在上一层目录生成压缩包，只装**对方打开就能用的东西**：

| 放进包 | 为什么不放那些 |
| --- | --- |
| `运营场景人机协作流程工具.html` | 主交付，双击即用 |
| `README.md` | 怎么看、怎么用 |
| `交付说明-两份工具怎么配合.md` | 两份工具的关系 |
| `模板/玩家反馈日报模板.md` | 能直接照着填 |
| `模板/试跑记录.md` | 证明真跑过、两轮引擎各查出什么 |

校验脚本、冒烟测试、注入密钥脚本、迭代记录、验证记录、调研与出处**都不进包**——对方手里没有 Python 环境，打开也没法跑，只会让人困惑。密钥明文 txt 同样排除。

打包后会扫一遍，确认包里没有明文密钥、页面确实带着可用凭据、必要文件齐全。

它把自检工具复制一份到 `_run/`、只改副本里的那两个字段、在副本里跑，**不改动 `运营自检/` 里的任何文件**。不带参数运行会列出所有可用类型。

**这个接口是被机器验过的。** 校验脚本每次都拿流程里写的类型、必含栏目、模块对照，去和 `运营自检/checklist.json` 逐项比对；自检工具的规则改了而本工具没跟上，校验会直接失败并指出差在哪。规则改动不会被无声吞掉。

## 四、每一步给什么，依据在哪

点开任一节点，能看到这几项：

| 项 | 说明 |
| --- | --- |
| 机器做 / 人做 | 一句话说清两边各干什么 |
| 交接 | 交接方向，以及为什么交接点落在这个位置 |
| 产出物 | 这一步交出来的是什么 |
| 机器要的 / 人拍的板 | 机器需要哪些信息、人要拍哪些决定 |
| 出错怎么办 | 如果出现某种情况，则怎么处理 |
| 依据 | 这一步标的替代档位、用了哪几条准则、为什么这么分，附出处 |

**每一步标的档位，评的是这一步里交给机器的那部分，不包含留给人判断的那部分。** 同一步里可以既有档一（打标的执行）又有档四（分类体系怎么定）。

**依据全部来自公开材料，不自己造：**

| 用到的部分 | 出处 |
| --- | --- |
| 五准则（量、规则清晰度、错误代价、数据可得性、判断需求）与四类处置 | ProcessCamp《How to Decide What to Automate with AI》 |
| 「人在回路不是免费的」这笔账 | Softomate《What AI Still Cannot Do》 |
| 任务适用性矩阵与四分类 | AICompetence《AI Task Design》 |
| 先审流程质量再自动化 | Algofuse《The Automation Trap》 |
| 四档替代程度 | 本项目 `../必要性论证.md` 第三节，由上述框架推出 |
| 岗位流程与检查项 | 游戏运营领域公开 SOP，见 `../运营自检/行业检查清单索引.md` |

行业检查项共 22 条登记在数据块里，每条标明出处与「范围内 / 范围外」；范围内 19 条必须能在流程的某一步找到归宿，校验脚本会检查。**这条检查是防漏步用的**——真实清单里的项如果在流程里没归宿，说明流程漏了环节，而不是清单多余。

## 五、边界

1. **它只给流程与分工，不判断内容对错。** 公告写得对不对、结论成不成立，仍要人回官方来源核。
2. **例外提示是关键词字面匹配，不是语义理解。** 换个说法就不触发，所以它只提醒、不替代人判断。
3. **输入涉及内部数据的任务，只覆盖人机分界，不覆盖取数。** 例如角色持有率、出战率只能来自公司内部埋点，流程能定义「该取哪些数、取来之后谁来判」，不能替人取数。
4. **判为范围外的检查项已逐条写明理由。** 客户端基础安全、性能与稳定性、服务器与运维属研发与运维职责，这条流程不接管。
5. **流程与规则来自公开材料。** 真实业务材料校准列入下一轮，见 `迭代记录.md`。

## 六、目录与校验

```
人机协作流程工具/
├── 运营场景人机协作流程工具.html    交付物。单文件，双击即用，带着访问凭据

├── verify_flows.py            数据校验：结构、六要素、交接点、RACI（A 必须是人）、依据、出处、
│                              行业检查项归位、岗位任务覆盖、自检工具对接、首屏文字量
├── smoke_test.js              功能校验：把页面脚本放进打桩 DOM 跑一遍
├── README.md                  本文件
├── 验证记录.md                各项校验的实际输出与结论
├── 调研与出处.md              流程、画法、判定各自从哪来：检索式 → 来源 → 结论 → 用途
└── 迭代记录.md                改了什么、为什么改
```

```
python verify_flows.py                                  # 数据与结构，通过时退出码 0

```
