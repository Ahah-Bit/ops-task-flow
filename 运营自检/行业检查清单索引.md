# 行业检查清单索引

> 用途：把行业里已经沉淀好的检查清单扒过来，作为本项目检查项的来源与校准依据。
>
> 原则：不照抄。行业清单面向的是"整个游戏上线"，本项目面向的是"运营交付物流转前的自检"，粒度不同。做法是提取其中**可迁移的检查维度**，再按运营场景重新组织。
>
> 收录日期：2026-09-21

## 一、游戏上线前安全自检

**来源：** 网易易盾《游戏上线前安全自检清单》

### 研发侧

| 检查维度 | 具体检查项 |
| --- | --- |
| 客户端基础安全 | 核心代码、关键资源、配置文件、版本更新、SDK 接入是否具备基础保护 |
| 关键接口安全 | 登录、支付、奖励、兑换、任务、排行榜、交易等接口是否有频控、校验、鉴权、日志记录 |
| 数据埋点完整性 | 环境、账号、行为、收益、内容、处置结果能否形成可追溯链路 |

**这条值得记住：** "高价值接口上线前必须完成风险评估"。以及"如果上线后才发现缺少关键日志，后续排查和复盘会非常被动"。

### 运营侧

| 检查维度 | 具体检查项 |
| --- | --- |
| 活动规则可被异常利用 | 签到、抽奖、兑换、邀请、排行榜、限时任务，需提前评估奖励价值与风险路径 |
| 处置策略是否分级 | 不能只有封禁一种动作，应准备观察、验证、限制、复核、隔离、处置等多种策略 |
| 客服与申诉准备 | 安全策略上线后会出现申诉与咨询，需提前准备复核流程与沟通口径 |

### 内容与数据合规

| 检查维度 | 具体检查项 |
| --- | --- |
| 内容审核策略 | 涉及聊天、昵称、头像、评论、UGC、语音、图片、直播互动的，上线前须配置审核策略 |
| 数据合规 | 用户授权、隐私提示、第三方 SDK、数据采集范围、存储与审计机制；多地区运营还需评估区域规则差异 |

**来源方的一句话，跟本项目的判断一致：** 自检清单不要靠临时会议，而要固化成版本流程；每次大版本、重大活动、渠道投放、新玩法上线前，都应完成自检并留下记录。

**常见遗漏项（来源方总结）：** 活动奖励风险、交易链路、客服申诉流程、内容审核策略、关键日志埋点。

## 二、合规审核的三级机制

**来源：** 游戏行业全流程合规指南

| 机制 | 具体做法 |
| --- | --- |
| 三级审核 | 研发自查 → 法务合规复核 → 负责人签字放行 |
| 留档备审 | 所有文案、美术、剧情、玩法截图留档 |
| 版号台账 | 版号编号、审批时间、对应版本、运营主体、授权链路、版本变更记录 |
| 上线前必答项 | 本次变更是否触发重新报审 |

**可迁移的点：** "上线前必答项"这个设计很好——把最容易忽略的风险做成一个必须回答的问题，而不是藏在清单里。

## 三、上线全流程节点

**来源：** 国内手游上线全流程解析、游戏产品上线全流程详解

| 阶段 | 关键节点 |
| --- | --- |
| 上线前筹备 | 版本验收与致命问题收敛；合规资质；物料与宣传；服务器与运维 |
| 灰度与试运营 | 小范围灰度测试，收集反馈，形成优化清单并在正式上线前完成修改 |
| 上线前收尾 | 渠道提交与排期；预热与开服活动准备 |

**可迁移的点：** "灰度测试结束后要形成优化清单，在正式上线前完成全部修改"——这一条把测试与修改串成了一个闭环，而不是测完就完了。

## 四、发布前检查清单（海外视角）

**来源：** Design The Game《Final Launch Checklist》

| 检查维度 | 具体检查项 |
| --- | --- |
| 法务文件 | 用户协议、隐私政策、服务条款 |
| 年龄分级 | 分级须准确反映游戏内容 |
| 知识产权 | 使用的素材必须已授权或为原创 |
| 无障碍 | 色盲模式、字号调节、按键重映射、字幕 |
| 性能与稳定性 | 长时间压力测试，检查内存泄漏、崩溃、性能衰减 |
| 异常场景 | 断网、断电、外设移除等场景的处理 |
| 最终构建 | 认证版本的版本控制与归档，确保可复现 |

**可迁移的点：** "异常场景处理"和"最终构建归档"这两项，在运营交付场景里对应的是"出问题时的回滚方案"和"这一版交付物是否可追溯"。

## 五、这些清单对本项目的具体用处

| 本项目的交付物类型 | 可从行业清单补充的检查维度 |
| --- | --- |
| 版本更新公告 / 游戏内文案 | 概率公示、活动规则可被异常利用、未成年人相关提示、法务文件引用 |
| 配置核对清单 | 关键接口的频控与鉴权、数据埋点完整性、处置策略分级、回滚与归档 |
| 活动复盘 / 分析报告 | 异常场景覆盖、灰度反馈闭环、上线前必答项 |
| 新增：版本上线自检 | 直接采用第一节与第三节的结构 |
| 通用 | 三级审核留痕、客服与申诉口径是否同步准备 |
